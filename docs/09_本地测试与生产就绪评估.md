# 本地测试与生产就绪评估

评估时间：2026-11-05，Asia/Shanghai。范围：当前工作区的后端、前端、工作流、数据访问与部署配置，以及本机只读检查和离线探针。

## 1. 结论与下一步

项目已有 Vue 页面、FastAPI 接口、数据库模型和七节点工作流，可以继续作为开发基础。但真实业务链路尚未闭环，当前不具备生产上线条件。

建议按以下顺序开发：

1. 建立独立、可重复启动的本地环境，解决端口和数据库凭据问题；同时修复认证、租户隔离和审核默认放行。
2. 打通一个真实 SKU 的“登录 → 创建商品 → 生成文案/图片 → 审核 → 编辑 → 下载真实交付包”流程。
3. 增加可靠的任务执行、重试、幂等和中断恢复，再扩展批次与视频。
4. 修复容器构建与数据库迁移，在预发布环境验证备份、恢复、升级和监控，再上线。

先把一期交付流程做实；多平台自动刊登按项目现有范围留到二期。

### 离线行为探针

以下是对当前代码的实际复现，不是推测。模型探针使用空 Key 或本地假响应；审核节点使用无 task_id 的状态并替换记录器，避免写业务数据。

| 场景 | 观察到的行为 | 应达到的行为 |
| --- | --- | --- |
| 不带 Token 请求 `/api/v1/auth/me` | HTTP 200，身份为 admin | HTTP 401 |
| 不带 Token 请求 `/api/v1/auth/refresh` | HTTP 200，并签发 access_token | 拒绝匿名刷新 |
| 不带 Token 连接 `/api/v1/ws` | 接受连接，ping 收到 pong | 认证通过且授权后才能订阅 |

| 审核返回 score=99、passed=0、violations=[] | is_passed=true | 尊重明确拒绝结果 |
| 商品为 ceramic mug | 关键词仍是 camping chair 等；主图提示词变为 Wireless Earphones Pro | 文案、关键词、图片提示词准确对应 SKU |

## 3. 必须修复的生产阻断问题（P0）

### P0-01 认证、权限和租户隔离

- `app/core/deps.py:23` 在无 Authorization 或非 Bearer 头时直接返回默认管理员，未使用 AUTH_ENABLED 控制行为。即使当前 AUTH_ENABLED=true，匿名请求仍能获得管理员身份。
- `/auth/refresh` 依赖同一逻辑，因此匿名用户能取得管理员 Token。
- 当前依赖直接接受解码后的 payload，未完整检查必需身份字段、令牌类型及用户/租户当前状态。关键管理路由也缺少按角色检查。
- `app/api/v1/ws.py:20` 无认证接入；广播发给所有连接，`app/agent/recorder.py:38` 的事件包含节点输出，缺少租户/任务级分发隔离。
- `app/services/batch_service.py:51` 按传入 SKU ID 创建任务，未先确认这些 SKU 属于当前租户；后台 `app/api/v1/tasks.py:38` 又只按 SKU ID 读取。两处结合存在跨租户取用商品数据的代码路径，需优先修复。该路径来自静态核对，未在真实双租户数据库执行攻击复现。
- 部分关联查询和更新只带对象 ID，缺 tenant_id/is_deleted 条件；素材登记也需验证 SKU 与 task 的租户归属。

验收：匿名 401；角色权限不足 403；另一租户的对象不可访问、不可关联创建、不可订阅；生产配置不能启用默认管理员回退。使用两个测试租户覆盖 HTTP、批量创建和 WebSocket。

### P0-02 审核会默认放行

- `app/agent/nodes/quality_reviewer.py:66` 默认 score=96、passed=1；解析失败沿用合格值。
- `app/agent/nodes/quality_reviewer.py:84` 最终判断只看分数和 violations，忽略解析到的 passed。
- 主工作流没有调用实时检查服务中的禁词规则。`app/services/compliance_service.py` 的实时接口又丢弃了 LLM 返回值，最终只按固定五个词判断，两套审核逻辑不一致。
- 当前审核仅提供文本截选、图片数量和视频是否存在，没有把实际图片/视频内容交给审核模型；不能据此证明视觉内容已审核。
- 导出接口未强制检查任务完成、最新审核通过或人工批准。

验收：无效 JSON、超时、模型不可用、明确拒绝、缺少必需产物均不能通过；规则命中可阻断导出；人工复核与修改后重审有记录。将自动检查和人工批准状态明确区分。

### P0-03 真模型失败仍被模拟结果掩盖

- `app/clients/provider_factory.py:45`、`:83`、`:204`、`:255`、`:308`、`:365` 在缺 Key 或请求失败时返回 Mock，未遵守 ALLOW_MOCK_ASSETS。
- `get_embedding` 失败返回固定向量，可能污染知识检索。已有测试向量需标记来源，正式启用真实 embedding 后重建受影响索引。
- `app/api/v1/providers.py:65` 将 Key 直接保存到名为 api_key_enc 的字段，实际未加密。
- ProviderFactory 只读取全局 Settings，没有读取界面保存的租户厂商配置；连通性测试也未使用正在测试的那条配置，可能出现“已保存但未生效”。

验收：开发 Mock 必须显式启用并清楚标识；正式模式缺凭据、401、429、超时均有真实失败状态；厂商配置保存、测试、工作流使用同一配置来源；Key 加密或引用专用密钥存储，日志与响应脱敏。

### P0-04 业务产出仍包含硬编码模板

- `app/agent/nodes/creative_planner.py:63` 没有解析模型返回的标题、五点和关键词，而是使用露营产品模板；language 写死 en。
- `app/agent/nodes/visual_designer.py:47` 将商品简单分为“名称含椅字”和“其他”，其他商品一律生成耳机提示词，模型生成的视觉方案没有驱动实际 Prompt。
- 多个节点直接向原始兼容 HTTP 接口发送 role=human，需按厂商接口契约统一为支持的消息角色；本轮没有真实 API 验证。
- 模型、语言、平台等任务参数未完整生效；`app/agent/graph.py:60` 固定执行图片再执行视频，未按 media_type 条件路由。
- 商品参考图片没有形成完整的生图输入链路；实际商品外形、颜色、标识一致性需要单独验收。

验收：至少选取三类不同商品，结构化解析模型输出，校验必需字段、规格事实与参考图一致性；平台、语言、媒体类型参数都能改变实际执行结果；仅生图任务不调用视频接口。

### P0-05 长任务、重试与失败状态不可靠

- 生成任务由 FastAPI BackgroundTasks 执行；Redis 当前只有客户端封装，没有实现可靠任务消费。
- `app/agent/graph.py:77` compile 未配置 checkpointer；节点快照表不等于可恢复的执行状态。
- 后台异常仅记日志；节点保存产物失败也可能被捕获后继续走成功流程，存在任务长期 running 或“完成但缺数据”的风险。
- 手动重跑缺少运行状态限制和原子占用；重试会重复插入 Copy/ComplianceReport，而详情和导出使用 scalar_one_or_none，可能因多条记录报错。
- 审核节点写数据库时使用旧 retry_count，但返回给路由的是增加后的值，达到上限时可能结束图却遗留 retrying 状态。
- 批次 completed_count/failed_count 创建后没有更新逻辑。

建议采用独立 Worker + 持久任务队列，配合 PostgreSQL checkpointer、执行轮次、幂等键和原子状态转换。队列负责可靠调度，checkpointer 负责工作流状态恢复，两者不能互相替代。FastAPI 对复杂后台任务的建议见[官方说明](https://fastapi.tiangolo.com/tutorial/background-tasks/#caveat)；持久化能力见[LangGraph 文档](https://docs.langchain.com/oss/python/langgraph/persistence)。

验收：提交后重启 API 或 Worker，任务不丢；已完成的付费调用不因恢复而无条件重复；失败有明确原因；重复点击不并发执行同一任务；重试历史可查，详情始终能取到明确版本的结果；批次统计最终收敛。

### P0-06 存储与交付闭环未实现

- 图片/视频节点主要保存厂商 URL，未形成下载、校验和转存到自有对象存储的业务链路。
- `app/clients/minio.py` 仅初始化客户端和桶辅助函数，没有被生成交付流程使用。
- `app/api/v1/packages.py:101` 返回固定的 mock-storage ZIP 地址，没有真正生成 ZIP。
- `frontend/src/views/PackageView.vue:57` 只弹窗展示链接，没有实际下载流程。

验收：真实媒体入私有桶，记录对象键、格式、大小、摘要和来源；生成包含文案、媒体、审核报告的真实交付包；按租户鉴权并签发短期下载地址；未通过审核的产物不可交付。转存外部 URL 时限制来源、大小、类型和网络访问范围。

### P0-07 生产构建和配置不能直接使用

- Dockerfile 在复制 README.md 与 app 之前执行 pip install .，与 pyproject 的 readme/package 定义不匹配；并且 COPY 了实际不存在的 run_workflow.py。属于静态可确认的构建缺陷，本轮未运行镜像构建。
- docker-compose.yml 后端环境变量未传入 SECRET_KEY、DEBUG 和模型 Key，也没有 env_file；Compose 读取根目录 .env 做变量插值不等于把所有变量传给容器。
- 后端镜像没有 COPY .env，按当前配置容器会使用开发 SECRET_KEY、DEBUG 默认值，并缺失模型凭据。
- Nginx 只监听 80，没有 TLS 证书和 443 server；映射 443 不等于启用了 HTTPS。
- 前端使用 history 路由，前端 Nginx 使用默认配置，缺少 SPA 回退，直接刷新深层路径可能 404。
- 开发与完整 Compose 使用同样的固定 container_name，且数据卷策略不同，后续易发生命名冲突或误判数据位置。

验收：从干净检出可按锁文件构建；生产启动拒绝弱密钥/DEBUG/Mock；迁移后可启动；HTTPS、WebSocket、深层页面刷新、下载均通过；开发和生产数据与配置相互独立。

## 5. 建议的开发批次与验收门槛

### 批次 A：本地开发基线和安全底座

交付：版本管理基线、独立端口和配置、本地启动/停止/诊断脚本、真实就绪检查、数据库迁移基线、认证/租户/审核修复、正式模式禁止 Mock。

本机 5173 与 5434 已占用，先选空闲端口并统一修改配置；例如可检查 5174、5435 是否空闲后使用，不能直接假设可用。基础设施开发端口建议绑定 127.0.0.1。使用隔离测试库，避免对当前 5434 服务重置密码、初始化或清空数据。

通过标准：按文档一次启动；前端明确展示本项目；就绪检查准确；两个测试租户的权限隔离检查通过；弱生产配置启动失败；审核异常不放行。

### 批次 B：完成一个可用的交付闭环

交付：统一租户模型配置、结构化文案/视觉生成、正确媒体分支、工作台事件、真实存储和 ZIP 下载、编辑后重审。

通过标准：三个不同类目 SKU 都可走通登录到下载；商品属性不串类目；生成错误可见；只生图任务不产生视频费用；交付包中的文件真实可打开；拒绝结果不能下载。

离线自动化先覆盖认证、租户隔离、审核拒绝、厂商超时/401/429、参数约束和下载权限。少量真实模型验收再验证规格事实、图片一致性、质量、耗时与费用，记录每次执行结果。

### 批次 C：可靠批量处理

交付：Worker、持久队列、checkpointer、幂等与轮次、失败收敛、重试/取消、预算和并发上限、批次统计。

通过标准：在执行中重启服务、注入厂商失败和存储失败，任务状态能正确恢复或失败；无重复并发与失控收费；工作台重连后能恢复状态。

### 批次 D：预发布与生产部署

交付：可复现构建、生产 Compose、独立配置和凭据、HTTPS/SPA/WebSocket、迁移执行步骤、备份/恢复/升级/回退说明、监控告警和 CI。

## 6. 生产发布前的最低验收清单

- [ ] 无匿名管理员、无跨租户读取/关联/订阅，关键操作按角色授权。
- [ ] 生产缺配置或模型故障会显式失败，模拟数据不会进入正式交付或向量索引。
- [ ] 审核解析失败、明确拒绝和规则命中均阻断交付；人工批准可追溯。
- [ ] 文案、图片提示词和媒体准确对应实际 SKU，平台/语言/媒体参数生效。
- [ ] 一个真实 SKU 能生成、存储、审核、编辑、重审、下载。
- [ ] 中途重启、重复提交和厂商故障不会导致丢任务、重复收费或永久 running。
- [ ] 干净环境镜像构建、迁移、HTTPS、深层页面刷新和 WebSocket 验证通过。
- [ ] PostgreSQL 与媒体都有可恢复备份，恢复和回退已演练。
- [ ] 关键错误、队列积压和费用超限可告警；日志包含定位信息且不泄露密钥。
- [ ] 本地测试、预发布与生产的数据库、对象桶、模型凭据明确隔离。

本轮完成的是首轮工程评估和聚焦行为复现；上述条目需在后续开发中逐项实现并验证。
