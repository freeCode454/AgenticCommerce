# 任务持久化、重启恢复与重复执行保护

更新日期：2026-11-06。本轮在本机开发环境验证，未部署生产环境，未调用真实付费模型。

## 已实现的行为

- 单任务、批次及手动重试统一使用 PostgreSQL 持久化队列，移除 FastAPI `BackgroundTasks` 临时调度。任务和排队记录在同一个事务中提交。
- 创建后为 `pending`，领取后为 `running`。每次完整重跑创建独立的 `ac_task_execution` 记录，保留起止时间、中断原因及历史产物、费用。
- 每个 API 进程自带异步执行器，默认并发 2 个任务。租户与任务共同生成的 PostgreSQL 会话锁防止多个进程重复执行；部分唯一索引防止同一任务同时有两个待处理或运行中的执行记录。
- 执行期间检查持锁数据库连接，失效后取消本机工作流。新模型请求和节点写入还会校验当前执行身份，阻止旧执行覆盖新结果。
- 完成、失败或恢复中断状态后，同步批次的实际完成数、失败数和状态。停用租户的排队任务直接失败，不发起模型请求。

## 重启恢复的边界

| 重启前状态 | 恢复后的行为 |
| --- | --- |
| 已保存、尚未领取 | 自动继续排队执行 |
| 正由其他健康进程执行 | 会话锁阻止重复领取，原进程继续 |
| 已领取、持锁进程消失 | 执行标记 `interrupted`，任务显示失败原因，等待用户确认后完整重跑 |
| 已完成或已失败 | 保持原状态，不自动再生成 |
| 旧版遗留的运行中任务，没有执行记录 | 标记中断，提示人工重试 |

数据库事务与外部模型请求不能组成一个原子事务。断线发生在厂商接收请求后，厂商可能继续生成并计费；取消本机协程不能撤销远端工作。因此本轮**不自动重跑中断任务，不承诺厂商调用恰好一次**。现有“重新生成”确认框会说明从头执行和再次产生费用。

本轮没有增加 LangGraph 中间状态检查点，也没有持久化厂商视频任务 ID 并接续轮询。中断后不会从某个节点自动续跑，这些需要后续按厂商能力实现。

## 请求去重与页面展示

- `POST /api/v1/tasks`、`POST /api/v1/batches` 支持可选 `Idempotency-Key` 请求头，长度 1–128。相同租户、入口、标识及内容复用已有资源；同标识用于不同内容返回 409。省略标识表示新的创建请求。
- `POST /api/v1/tasks/{task_id}/run` 同样支持标识。即使第一次响应丢失、任务后来完成，相同标识也不会再次生成。排队和运行中的任务禁止再次排队，返回 409。
- 前端创建任务、批次及手动重跑均发送标识；网络失败后保留，修改表单或确认成功后更新。
- 既有 REST 路径和请求体不变。任务详情补充 `execution_id`、`error_message`，节点补充 `execution_id`；前端已有 `pending` 状态支持。
- 工作台显示排队说明和真实中断原因，只展示当前完整执行的节点和产物；交付清单也按当前执行筛选。素材/文案管理及费用汇总保留历史记录。
- 正在执行的当前文案禁止人工编辑。编辑历史文案不影响当前任务审核；编辑当前已结束的文案仍会使审核失效，并同步批次状态。
- 排队和运行中的任务每 5 秒只读刷新，即使当前 WebSocket 正常也刷新，支持任务由其他 API 进程执行的情况。
- 审核重试上限修正为额外重试次数：0/1/2 分别最多执行 1/2/3 轮生成。

## 运行与迁移

迁移 `b82f91d4e630` 新增执行表、请求标识与指纹、任务当前执行标识，以及文案/素材/审核/节点的执行标识。没有物理外键，不修改原有产物内容。旧记录的执行标识为空，兼容原数据。

更新源码后使用项目启动脚本，原有流程会先执行迁移：

```powershell
pwsh -NoProfile -File scripts/dev.ps1 -Action Start
```

如已有本项目的服务或进程记录，先使用 `Stop` 再 `Start`。手动启动时先执行 `.venv\Scripts\python.exe -m alembic upgrade head`。本次已在忽略的 `data/backups/` 备份本地数据库后迁移，未改动其他项目数据库。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `TASK_WORKER_ENABLED` | `true` | 当前进程是否领取任务；关闭后接口仍可保存排队请求 |
| `TASK_WORKER_CONCURRENCY` | `2` | 每个 API 进程的并发数，1–8；多进程总并发累加 |
| `TASK_WORKER_POLL_SECONDS` | `1` | 队列扫描间隔，秒 |
| `TASK_WORKER_HEARTBEAT_SECONDS` | `2` | 持锁连接检查间隔，秒；单次检查超时 3 秒 |

会话锁要求数据库会话保持不变，当前直连 PostgreSQL 满足这一条件。如果以后引入 PgBouncer，持锁连接必须直连或使用会话池，不能使用事务池。生产容量、全局限流、取消任务、独立 worker 部署和远端任务接续仍待后续验收。
